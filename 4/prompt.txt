## Detection guidance
- **Forward-compat version gates (FCLEN, FCCPV, FCDQS, FCFAV, FCHBL, FCLFS, FCNVA)**: these are **forward-compatibility** checks — flag a language feature that requires a newer MATLAB than the code's target. Since mlt targets "current MATLAB", interpret them as: detect the language construct and emit the check. Concretely:
  - FCLEN: an identifier longer than 63 characters.
  - FCCPV: a class property with validation (a `properties` block property having a type constraint / validation function).
  - FCDQS: a double-quoted string literal (`"..."`).
  - FCFAV: a function with an `arguments` block.
  - FCHBL: a hex (`0x...`) or binary (`0b...`) literal (a `number` node starting with `0x`/`0b`).
  - FCLFS: a script file containing a `function_definition` after non-function statements (local functions in a script).
  - FCNVA: `Name=Value` syntax in a function call (an `=` token inside `arguments` where left is an identifier).
- **REDEFGI/REDEFGG**: `global` declarations. REDEFGI when a function input/output variable is also declared global; REDEFGG when the same variable is declared global more than once. Use the symbol table (`crate::analysis::symbols::SymbolTable`) if helpful — build it from the tree in a file-level pass.
- **NSTIMP**: nested function inherits import statements — detect a nested `function_definition` whose parent function has an `import` before it; fire on the nested function (informational).
- **IMPIVD/IMPKEY**: `import` statements. IMPKEY when importing a reserved word; IMPIVD when the import argument is malformed. Detect `import` command/function calls.
- **SHVAI/IDISVARHIGH/IDISVARLOW**: unset-variable style. These overlap with the Unset Variables engine (already implemented). Implement conservative versions:
  - SHVAI: a nested function uses a variable not defined in its parent before the nested call.
  - IDISVARHIGH/IDISVARLOW: a variable used before definition. Use the symbol table. If this is too overlapping with the existing unset_variables engine, implement a minimal version and note it. Favor the symbol-table approach.

Note: some of these (esp. the version gates) are straightforward AST-pattern checks; the scope/unset ones can use `SymbolTable`.
